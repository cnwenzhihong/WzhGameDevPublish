蓝图

角色蓝图

Lyra的Character只提供与外接系统沟通的最小功能
角色继承关系:

[list2astreeH|code()]

  • 📄LyraCharacter——底层系统支持
    • 📘CharacterDefault——无逻辑，蓝图基类
      • 📘B_Hero_Default——控制器支持、声音特效组件
        • 📘B_Hero_ShooterMannequin——模型表现支持
        • ❎B_Hero_Arena(炸弹人游戏玩法)
        • ❎B_Pawn_Explorer B_Hero_Explorer(StateTree测试)

LyraCharacter

为新的系统接入提供基础支持。如GAS、模块化、相机控制、队伍管理

  • 模块化组件支持——继承自ModularCharacter
  • GAS函数支持
  • 变量
    • MovementMode映射Tag(MovementModeTagMap)
    • 加速度的网络同步(ReplicatedAcceleration)
  • 简单功能: 生命值组件、相机组件、队伍ID
  • 参数修改：关闭Tick、更改碰撞和网格体的碰撞预设、设置几乎无限远的网络同步距离

CharacterDefault

给所有蓝图Character类一个父类
只改了胶囊体的Area Class Override为空Obstacle

B_Hero_Default

增加一些Character必要的控制器(玩家输入、AI)功能，处理一些通用效果(死亡、脚步)以及配套的(处理脚步声)特效管理组件LyraContentEffect

  • 管理输入和相机：LyraHero组件
    • InputData_Hero：输入表格
  • AI:
    • AI感知:AIPerceptionStimuliSourceComponent，添加视觉、听觉感知
    • AI加减速更自然: 勾选MovementComp的Use Acceleration for Paths
  • 处理死亡的表现效果(所有函数)：
    关闭碰撞、隐藏所有直系模型，帮武器组件隐藏武器、布娃娃
  • 表现——处理动画通知发来的脚步声:
    • 特效、声音处理: LyraContextEffectComponent
    • 脚步效果: 实现LyraContextEffectComponent的AnimMotionEffect接口——创建B_FootStep并把所有对该接口的调用都扔进去

B_Hero_ShooterMannequin

做基本的射击角色配置，对自定义模型提供支持

  • 射击相关:
    • 修改移动相关参数
    • AimAssistTarget瞄准辅助的目标端
  • 角色模型:
    • Mesh添加骨骼模型和配套的动画蓝图
    • PawnCosmeticsComponent管理角色骨骼模型，见:#模型管理
  • UI:
    • 在LAS_ShooterGame_StandardComponents动态添加了铭牌NameplateSource组件，可以不视作上文的一部分

模型管理

原理

将所有角色表现相关的逻辑独立出来。很容易做各种判断，比如：如果是独立服务器的话，完全没必要创建模型。FPS第一人称模型只需要本地生成即可。
同时直接在代码层将所有模型碰撞等参数统一处理。

实现

大体逻辑

  1. Mesh——实际要显示的内容
    📝ALyraTaggedActor
    📘B_Manny 📘B_Quinn
    • 供显示的模型——MeshComp
    • 反向决定主模型——StaticGameplayTags
  2. 选择器——要选哪个Mesh
    📝ULyraControllerComponent_CharacterParts
    📘B_PickRandomCharacter
    • BeginPlay时通知生成哪个即可——AddCharacterPart
  3. 生成器——创建选好的Mesh
    📝ULyraPawnComponent_CharacterParts
    📘B_MannequinPawnCosmetics
    • 生成Mesh实例并Attach到Character的主Mesh
    • 根据Mesh的Tag更换主Mesh(男性女性骨架)
    • 存储Handle——CharacterPartList 
      FLyraCharacterPartList::AddEntry

详细流程

  1. Experience自动将PickRandomCharact生成到Controller
  2. PickRandomCharact随机选择一个TaggedActor发送给PawnCosmeticsComponent
  3. PawnCosmeticsComponent将其Attach到Mesh下
  4. PawnCosmeticsComponent根据TaggedActor的标签匹配合适的主Mesh

TaggedActor

蓝图子类B_Manny和B_Quinn。
提供Mesh和Tag反选合适的主Mesh，动画蓝图使用Copy

ULyraControllerComponent_CharacterParts

选择器，给蓝图子类提供直接调用选择的接口——AddCharacterPart
其蓝图子类B_PickRandomCharacter根据自己想要的规则选择一个Class

B_PickRandomCharacter由ExperienceDefine的AddComponent中添加到Controller中

ULyraPawnComponent_CharacterParts

直接被添加到角色的组件中:

Character中Mesh模型的选择

MeshRules包含Tag和模型。其用于反过来确定Character的SkeletalMesh。

 FGameplayTagContainer CosmeticTags = CharacterPartList.CollectCombinedTags();  

for (const FLyraAnimBodyStyleSelectionEntry& Rule : MeshRules)  
    {       
	    if ((Rule.Mesh != nullptr) && CosmeticTags.HasAll(Rule.RequiredTags))  
	       return Rule.Mesh;  
    }

❓为什么只改Mesh不改AnimBP？
如果只改Mesh的话，同一个骨骼并不会产生区别。

回调

在角色蓝图中增加了回调处理Team相关逻辑

蓝图配置流程

  1. 在玩法相应的Definition中添加给Controller的模型选择方案
  2. 该方案提供要生成的模型Actor类以及必要参数
  3. 该Actor自行决定要如何添加骨骼网格体。B_Manny中直接复制原Character中的动画蓝图到自己的骨骼

UE内置的队伍接口

概述

团队功能在引擎中用于AI感知(AIPerception)，实现在AI模块，而非独立的功能模块。
仅用于区分敌我简单的int标识，功能简单应用较少。

实现

FGenericTeamId：用uint8的ID来标识队伍，足够了。
IGenericTeamAgentInterface：设置、获取接口，比较函数接口+默认实现。

接口实现：AIController

接口应用：FAISenseAffiliationFilter::ShouldSenseTeam

敌我标识ETeamAttitude:

  • Friendly：默认实现 -> ID相同
  • Hostile：默认实现 -> ID不同
  • Neutral：TeamID不实现FAttitudeSolverFunction函数

Note

#### 敌我判断的实现细节

大多数情况下override中IGenericTeamAgentInterface的比较函数就足以完成需求，此处仅用作C++动态函数的范例记录

如上述代码，比较提供了默认实现，靠FGenericTeamId内部实现。采用动态函数

比较两个队伍的关系的动态函数定义：

//1. 定义函数类型
typedef TFunction<ETeamAttitude::Type(FGenericTeamId, FGenericTeamId)> FAttitudeSolverFunction;

同时提供了默认比较函数：DefaultTeamAttitudeSolver

//2. 定义函数默认实现
ETeamAttitude::Type DefaultTeamAttitudeSolver(FGenericTeamId A, FGenericTeamId B)
{
	return A != B ? ETeamAttitude::Hostile : ETeamAttitude::Friendly;
}
//3. 赋值
FGenericTeamId::FAttitudeSolverFunction FGenericTeamId::AttitudeSolverImpl = &DefaultTeamAttitudeSolver;
//4. 使用
static ETeamAttitude::Type GetAttitude(FGenericTeamId TeamA, FGenericTeamId TeamB)  
{  
    return AttitudeSolverImpl ? (AttitudeSolverImpl)(TeamA, TeamB) : ETeamAttitude::Neutral;  
}

Lyra的队伍功能框架

UE内置TeamID和接口功能较少，仅能作为基础建设。
其设计也不符合Lyra Framework随插随用的设计逻辑，该模块需要存储更多功能、方便使用。

  • 组件化：即插即用，ModularGameplay
  • 更多信息存储：队伍静态信息、动态信息需要有第地方存放和方便读取
  • 参数化：方便设置团队配置

配置

参考蓝图：B_TeamSetup_TwoTeams

  • TeamsToCreate
    团队ID(int)到Team静态信息的映射
    Lyra中通过红蓝区分两个队伍
  • PublicTeamInfoClass：Team数据类型，存放Team的所有信息
    动态数据：如CS中当前团队总分数、Lyra中的队伍占点数、总击杀数。Lyra中用更具灵活性的TeamTags替代int
    静态数据：存放自己队伍的TeamsCreate中的静态数据(TeamDisplayAsset)
  • PrivateTeamInfoClass：同上，仅自己队伍可以知道的数据
    Lyra中没有需要Private的数据

应用

下面四个类都继承了接口

  • PlayerState：存放队伍信息数据
  • Controller：传递PlayerState的队伍信息
  • Character：在Poccess的时将Controller的队伍信息赋给自己
  • LocalPlayer：同样仅作传递

Tip

Team数据的存放

在TeamsToCreate中的ULyraTeamDisplayAsset存放队伍的静态信息，如果仅需要这些信息，直接通过TeamsToCreate查询即可。
但队伍往往还需要存放一些需要同步的动态数据，如CS中的分数、总杀敌数等等。
Lyra中采用AInfo来存放和同步这些数据，为了便于管理，将静态数据也存入其中。

  1. 创建ALyraTeamPublicInfo，Actor类型：PublicTeamInfoClass和PrivateTeamInfoClass`
  2. 存入ID和静态数据ULyraTeamDisplayAsset
  3. 将创建好的info存入到ULyraTeamSubsystem::TeamMap

Info

ALyraTeamPublicInfo

继承自AInfo，不存坐标，属性可以同步
实际的数据存储在ULyraTeamSubsystem的TeamMap中

ULyraTeamSubsystem

UWorldSubsystem
管理所有Team信息

TeamMap

每个ID存储PublicInfo、PrivateInfo、DisplayAsset均为ULyraTeamCreationComponent配置并创建的内容，合并在一起统一管理

Important

TMap的属性同步问题

TMap不支持属性同步，其依靠TeamInfo同步后重新Register来曲线救国。
TeamInfo创建时在Beginplay注册自不必说，修改动态数据时在Set 、OnRep函数中也均重新注册

Team管理

  1. 注册、删除、寻找Team信息

    • 添加：RegisterTeamInfo
    • 删除：UnregisterTeamInfo
    • 获取：FindTeamFromActor、DoesTeamExist、GetTeamDisplayAsset

  2. Team信息改变时回调
    GetTeamDisplayAssetChangedDelegate：供外部绑定的静态数据回调
    没有TeamInfo中的动态数据改变回调

  3. 判断敌我：CompareTeams
    如UE的原生Team，同样为三种情况：
    ELyraTeamComparison：OnSameTeam、DifferentTeams、InvalidArgument
    同样是相同则同队，INVALIDE则InvalidArgument

void ULyraTeamSubsystem::Initialize(FSubsystemCollectionBase& Collection)
{
	Super::Initialize(Collection);
	
	auto AddTeamCheats = [](UCheatManager* CheatManager)
	{
		CheatManager->AddCheatManagerExtension(NewObject<ULyraTeamCheats>(CheatManager));
	};

	CheatManagerRegistrationHandle = UCheatManager::RegisterForOnCheatManagerCreated(FOnCheatManagerCreated::FDelegate::CreateLambda(AddTeamCheats));
}

void ULyraTeamSubsystem::Deinitialize()
{
	UCheatManager::UnregisterFromOnCheatManagerCreated(CheatManagerRegistrationHandle);

	Super::Deinitialize();
}

/** Cheats related to teams */
UCLASS()
class ULyraTeamCheats : public UCheatManagerExtension
{
	GENERATED_BODY()

public:
	// Moves this player to the next available team, wrapping around to the
	// first team if at the end of the list of teams
	// 将此玩家移动至下一个可用的队伍，若已处于队伍列表的末尾，则会自动回到第一个队伍。
	UFUNCTION(Exec, BlueprintAuthorityOnly)
	virtual void CycleTeam();

	// Moves this player to the specified team
	// 将此玩家移至指定队伍
	UFUNCTION(Exec, BlueprintAuthorityOnly)
	virtual void SetTeam(int32 TeamID);

	// Prints a list of all of the teams
	// 打印出所有团队的列表
	UFUNCTION(Exec)
	virtual void ListTeams();
};

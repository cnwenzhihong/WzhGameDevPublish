1.3. 确认TargetData

3.1 WeaponStateComponent处理

ULyraWeaponStateComponent::AddUnconfirmedServerSideHitMarkers
逐个Hit塞入未经证实数组中UnconfirmedServerSideHitMarkers

  1. TargetDataId
  2. 物理材质区域Tag
    1. GamePlay.Zone
    2. 该Tag主要用于记录弱点(爆头)

      在WeaponInstance中可以改变爆头伤害倍率

3.2 OnTargetDataReadyCallback 处理

ULyraGameplayAbility_RangedWeapon::OnTargetDataReadyCallback

Note

开始双端执行

主控端先执行，中间把TargetData传到服务器，服务器通过TargetData回调执行该函数

3.2.1 将TargetData Move到函数内

需要注意TargetData的传递，尽量用Move

//TargetDataHandle操作
FGameplayAbilityTargetDataHandle LocalTargetDataHandle(MoveTemp(const_cast<FGameplayAbilityTargetDataHandle&>(InData)));

// 移动构造函数 示例与作用
Resource(Resource&& other) noexcept { 
	data = other.data; // 获取其他对象的内存资源 
	other.data = nullptr; // 将原对象的指针置为空，防止析构时释放已转移的内存 
}

3.2.2 服务器验证TargetData

  1. 将TargetData发送到服务端，确保两端一致
  2. 服务器端：
    1.1. HitReplaces——对需要被替换的Hit的Id进行统计(前面并没有对TargetData的bHitReplaced进行过任何处理)，应该是采用默认Scope预测方案

3.2.3 客户端得到最终结果

WeaponStateComponent->ClientConfirmTargetData(HitReplaces)

  1. 客户端将已被确认的UnconfirmedServerSideHitMarkers数据(没有bHitReplaced)放入LastWeaponDamageScreenLocations中处理(没有找到改内容被使用的地方)
  2. 更新最近一次成功击中的时间

3.2.4 处理开枪逻辑

  1. CommitAbility —— 看是否有子弹，没有就结束
  2. 计算扩散——WeaponData->AddSpread
  3. 将TargetData发给蓝图—OnRangedWeaponTargetDataReady(LocalTargetDataHandle);
  4. 销毁TargetData——ConsumeClientReplicatedTargetData

1.4. 总结

4.1 设计思路

  1. 只在客户端进行射线检测，然后把Hit数据发到服务器
  2. 完整的服务器验证逻辑，实际上什么都没验证
  3. WeaponStateComponent存了LastWeaponDamageScreenLocations和最近一次成功的时间
  4. 最后把Hit结果发给客户端和服务器的蓝图函数OnRangedWeaponTargetDataReady处理

4.2 想法

  1. 范围检测先用射线检测的价值？
    1. 是否存在射线能击中一个但漏掉范围检测的情况
    2. 已经是仅客户端检测且非Tick，是否需要如此优化
  2. 客户端发送RPC让服务器获取到TargetData并广播，最后调用到OnTargetDataReadyCallback以实现双端都执行
  3. 服务器对bReplaced的处理，在什么地方会用到

穿透特效问题

只有Hit才播放，使用Weapon_Multi通道不会触发特效。只有Hit的Actor才会得到确实的物理材质
原因：CollisionPreset中WeaponMulti射线对PawnCapsule是OverLap，我们需要改为Ignore让其和Weapon一样打到Mesh上

此时，我们可以看到受击面，但依旧无法看到击中的火花特效

其实，火花特效已经生成，不过是在目标的ActorLocation而非受击点
要火花，我们需要找到TakeDamage的GC——GCNL_Character_DamageTaken
通过不断寻找代码，可以发现，FGameplayCueNotify_PlacementInfo::FindSpawnTransform中对bBlockingHit进行了判断

if (SpawnContext.HitResult && SpawnContext.HitResult->bBlockingHit)

    bSetTransform = true;  
}  
else if (!CueParameters.Location.IsZero())  
{  
    OutTransform = FTransform(CueParameters.Normal.Rotation(), CueParameters.Location);

3.2. 正式计算伤害

基础伤害=开枪者BaseDamage属性+手枪GE固定加成
开枪者BaseDamage属性：在Lyra中为0
手枪GE固定加成：18

ULyraDamageExecution

  1. TeamSubsystem判断是否能造成伤害CanCauseDamage
    默认是可以伤害自己的，猜测用于治疗-damage
    不同队可以，没有团队信息但又ASC也可以
  2. 计算距离Distance
  3. 计算物理材质衰减
    ILyraAbilitySourceInterface::GetPhysicalMaterialAttenuation
    其中ULyraRangedWeaponInstance通过MaterialDamageMultiplier找到Tag对应的乘数得到结果，身体1 WeakShot弱点2
  4. 计算距离衰减乘数
    ILyraAbilitySourceInterface::GetDistanceAttenuation
    ULyraRangedWeaponInstance中通过DistanceDamageFalloff曲线确定
  5. Damage=基础伤害与衰减相乘

5.4. 总结

WeaponAudioFunctions

对音效参数进行处理和传入，不管创建等生命周期，也就不需要有实体，应该只是为了整合所有音效操作才写成一个函数库

MusicManager

为对氛围音乐mx_system的控制，mix（环境音效，阴间状态音效），不涉及其它任何系统、音效。
Intensity精细控制权重
开火、受击和死亡时会增加阴间音效比重
受击和死亡被动监听消息，开火则

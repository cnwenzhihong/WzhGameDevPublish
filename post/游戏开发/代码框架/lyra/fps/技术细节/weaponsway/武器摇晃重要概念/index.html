类型1——视角旋转的惯性可视化

参考游戏

Battlefield 1\
OW 半藏

Weapon Sway 的本质分类框架

Weapon Feel is control engineering, not animation polish

从控制系统与信号处理角度，Weapon Sway 可以被严格分为以下 6 大类（并非按游戏，而是按系统性质）：
杀戮地带2:枪托旋转+Yaw延迟，体现重量感，同时手臂转动较慢
值得一提的是：游戏很容易沉浸，低昂的背景音家时不时队友的声音+脚步声哪怕没有敌人也足够沉浸 13:15
哪怕没有明显背景音乐也会有底噪工业废土艺术/10年前《杀戮地带2》多人联机战区模式实况

编号 风格名称 系统阶数 输入信号 代表游戏 视频
I 直接输入映射型（Direct Input Mapping） 0 阶 角速度 三角洲
II 一阶惯性滞后型（First-order Lag） 1 阶 角速度 CS、Valorant
III 二阶物理弹簧型（Second-order Spring） 2 阶 角速度 / 加速度 CoD
IV 混合控制型（Hybrid Control） 1–2 阶 多信号 Battlefield
V 状态机驱动型（State-driven / Authored） 离散 状态 Uncharted
VI 生物力学 / 感知模型型（Biomechanical / Perceptual） 非线性 感知变量 Tarkov（部分）
弹簧：
  • 二阶系统储存能量 → 感知到的重量
  • 受控的振荡能增加视觉丰富度
  • 适用于非以精确瞄准为首要目标的场景

一阶实现——CS

一、CS 风格 Weapon Sway

CS 的 weapon sway 是“受限的一阶滞后系统”，不是二阶弹簧系统

CS 的鼠标旋转武器摇晃 ≠ 物理真实 ≠ 弹簧系统
它的核心特征是：

  1. 输入驱动（Input-driven），而不是物理模拟驱动
  2. 只对“角速度”响应，不对加速度、不对惯性
  3. 几乎没有 Yaw 轴旋转（或极小）
  4. 即时响应 + 快速回正（无震荡）
  5. 幅度极小，但方向极准（反向跟随鼠标）

二、CS Weapon Sway 的设计原则

1️⃣ 只使用「角速度」，不用加速度

CS 的 sway 本质是：
WeaponOffset ∝ -MouseAngularVelocity

  • 不关心“你之前转得有多猛”
  • 只关心“你现在每秒转多少度”
  • 没有预测（lead），没有惯性积累
    这就是为什么 CS 永远不抖、不爆数值、不超前

2️⃣ 没有真正的 Yaw 摆动

你之前问的那句话正是 CS 的核心思想之一：

a weapon typically doesn’t move much on the yaw axis…

原因是：

  • Yaw 摆动会让枪口左右漂移，影响准星—枪口一致性
  • CS 的枪是“肩托为旋转支点（butt stock pivot）”
  • 左右转向主要体现在 位置平移 + Pitch/Roll 微旋转
    结论：
  • Yaw rotation ≈ 0 或极小
  • 用 位置 X/Y + Pitch/Roll 表现“跟手感”

3️⃣ 立即跟随，但快速回正（一阶系统）

CS 的回正逻辑是：

  • 松手后立刻回正
  • 没有 overshoot（不超过 0）
  • 没有 oscillation（不震荡）
    这不是弹簧，而是：
    Current = Lerp(Current, Target, Alpha)

为什么 CS 的 Weapon Feel 能形成“肌肉记忆”

Pitch / Roll 是“装饰轴”，Yaw 是“功能轴”。

先给一句工程级定义，防止概念漂移：

在 FPS 中，“肌肉记忆”并不是记住动作，而是：
人类神经系统对一个稳定、可预测、可逆的输入-输出映射的长期内化。

神经系统视角

Overshoot = 系统存在 隐含状态
隐含状态 = 神经系统必须“猜”系统当前在什么状态

人脑极其讨厌“猜系统状态”
一旦需要猜，肌肉记忆就退化为“手感适应”，而非固化记忆。

4. 为什么 CS 能形成“跨年不丢失”的肌肉记忆

因为它满足了人类运动学习的黄金三条件：

条件 CS 是否满足
映射线性 是
映射稳定 是
可逆性强 是
这使得神经系统可以：
  • 建立前馈模型（不用看反馈）
  • 直接预测所需输入
  • 在高压环境下自动执行

三、数学模型（CS 风格的“正确抽象”）

1️⃣ 输入信号（唯一来源） 

FRotator DeltaRot = NormalizedDelta(ControlRot, LastControlRot); FVector2D AngularSpeed = FVector2D(DeltaRot.Yaw, DeltaRot.Pitch) / DeltaSeconds;

然后做一件非常 CS 的事：

AngularSpeed /= MaxTurnSpeed; // 归一化 
AngularSpeed.X = Clamp(-1, 1);
AngularSpeed.Y = Clamp(-1, 1);

CS 非常讨厌无限值

2️⃣ 构造“理想 sway 目标（Target）”

CS 风格的映射（经验公式）：

TargetOffset.X = -AngularSpeed.X * SwayX;   // 左右转 → 枪反向滑 
TargetOffset.Y = 0.f; 
TargetOffset.Z =  AngularSpeed.Y * SwayZ;   // 上下看 → 枪上下滑  
TargetRot.Pitch = -AngularSpeed.Y * PitchRot; 
TargetRot.Yaw   = 0.f;                      // 几乎不用 
TargetRot.Roll  = -AngularSpeed.X * RollRot;

注意几个 CS 特征：

  • 方向几乎全是反向
  • Yaw = 0
  • Roll 比 Pitch 更明显

3️⃣ 插值方式（这是 CS 的灵魂）

❌ 不用 VectorSpringInterp
❌ 不用 Mass / Damping / Oscillation
✅ 用一阶指数衰减

float FollowSpeed = bHasInput ? 20.f : 30.f; 
// 松手更快回正 
float Alpha = 1.f - FMath::Exp(-FollowSpeed * DeltaSeconds);  
SwayOffset = FMath::Lerp(SwayOffset, TargetOffset, Alpha); 
SwayRot    = FMath::Lerp(SwayRot, TargetRot, Alpha);

这一步非常重要：

  • Exp(-k·dt) → 帧率无关
  • 没有震荡
  • 没有 overshoot
  • 完全可控
    这正是 CS 的 feel 来源之一

四、UE5 中的「最小 CS 风格实现示例」

在你现有函数的基础上，这是最接近 CS 的版本：

void WeaponSway_CSStyle(
    FVector& SwayOffset,
    FRotator& SwayRot,
    FRotator& LastControlRot,
    float DeltaSeconds,
    bool bHasInput)
{
    FRotator CurrRot = GetPawn<APawn>()->GetControlRotation();
    FRotator DeltaRot = UKismetMathLibrary::NormalizedDeltaRotator(CurrRot, LastControlRot);
    LastControlRot = CurrRot;

    FVector2D AngularSpeed(DeltaRot.Yaw, DeltaRot.Pitch);
    AngularSpeed /= DeltaSeconds;

    const float MaxTurnSpeed = 720.f; // CS 风格
    AngularSpeed /= MaxTurnSpeed;
    AngularSpeed.X = FMath::Clamp(AngularSpeed.X, -1.f, 1.f);
    AngularSpeed.Y = FMath::Clamp(AngularSpeed.Y, -1.f, 1.f);

    FVector TargetOffset;
    TargetOffset.X = -AngularSpeed.X * 2.0f;
    TargetOffset.Y = 0.f;
    TargetOffset.Z =  AngularSpeed.Y * 1.5f;

    FRotator TargetRot;
    TargetRot.Pitch = -AngularSpeed.Y * 2.0f;
    TargetRot.Yaw   = 0.f;
    TargetRot.Roll  = -AngularSpeed.X * 3.0f;

    float FollowSpeed = bHasInput ? 22.f : 35.f;
    float Alpha = 1.f - FMath::Exp(-FollowSpeed * DeltaSeconds);

    SwayOffset = FMath::Lerp(SwayOffset, TargetOffset, Alpha);
    SwayRot    = FMath::Lerp(SwayRot, TargetRot, Alpha);
}

五、CS 风格 vs 弹簧方案

项目 CS 风格 你当前方案
系统阶数 一阶 二阶
是否震荡 ❌ ⚠️
是否超前 ❌ ⚠️（lead）
数值稳定性 极高 中
调参成本 低 高
手感一致性 非常强 易漂
竞技适配 完美 一般
这也是为什么：
  • CS / Valorant / R6 几乎不用弹簧
  • CoD / Battlefield 才大量用物理 sway

六、什么时候“不要做成 CS 风格”

不推荐 CS 风格的情况：

  • 强沉浸、写实射击（Tarkov、Insurgency）
  • 有明显武器重量、惯性表达
  • 需要“慢启动 + 余震”
  • 右键瞄准
    弹簧系统是优势

二阶参数——SpringInterp

人类将"沉重感"与以下特征关联：

  • 缓慢的加速
  • 缓慢的减速
  • 非对称响应（启动快于恢复）
    可以在不用弹簧的情况下实现

1. SpringInterp 的真实身份

SpringInterp ≠ “更高级的插值”
它是一个：

二阶动态系统（Second-order dynamic system）

数学本质：
$m x'' + c x' + k (x - target) = 0$

也就是说，它必然：

  • 存储能量
  • 引入相位延迟
  • 可能产生 overshoot

2. Spring 系统与 FPS 输入的根本冲突

2.1 FPS 是“人类-系统闭环” 

Human → Mouse → Game → Visual → Human

而 SpringInterp 是：

  • 设计给 物理系统
  • 假设系统外部不做实时误差修正
    但玩家会 每一帧修正误差。
    这就形成了：

双重控制器叠加（Human + Spring），这是控制工程里的大忌。

3. SpringInterp 为什么“看起来很好用”

3.1 原因一：短期效果非常“顺”

  • 自动平滑
  • 自动回弹
  • 自动“有重量感”
    对 Demo / Showcase / 新手体验 非常友好。

4. SpringInterp 在 FPS 中的四个致命问题

人类不是刚体系统

问题一：隐性状态不可感知

玩家不知道：

  • 当前弹簧拉伸多少
  • 当前速度是多少
    神经系统无法建模。

问题二：相位延迟破坏预测

即便 Critical Damping：

  • 仍然存在时间延迟
  • 延迟是速度相关的（非固定）
    这直接破坏前馈控制。

问题三：Overshoot 等价于“假输入”

当玩家停手：

  • Weapon 还在动
  • 但输入为 0
    这在神经系统中被理解为：

“系统在我没动时产生了动作”

5. 为什么 Spring 在非竞技 FPS 里“还能活着”

因为这些游戏：

  • 不要求精确肌肉记忆
  • 接受“感觉重 / 晃 / 漂”
  • 玩家目标是沉浸，而不是可预测性
    例如：
  • Tarkov
  • Metro
  • Single-player CoD

6. SpringInterp 的正确使用场景（非常少）

Spring 应该只用于：

场景 是否合理
Idle sway ✔
Reload secondary motion ✔
非瞄准状态 ✔
Competitive aiming ✘
ADS 精准射击 ✘

7. 终极结论（非常重要）

关于 CS Weapon Feel

CS 的手感不是“简单”，而是“在控制论上极端克制”。

关于 SpringInterp

SpringInterp 最大的罪过不是“不真实”，而是“破坏可学习性”。

人类感知

人类感知定义的是硬性上限，而非建议值
最佳的武器手感应低于意识感知阈限

4.1 角度移动感知

  • 静态朝向感知的最小可觉差≈0.2–0.3°
  • 动态角度变化检测阈限低于 0.1°
  • 启示：武器旋转若超出上述限度，将被玩家有意识地察觉。

4.2 滞后感知

人类感觉运动循环的阈值：

  • <20 毫秒：感知为即时响应
  • 20–30 毫秒：勉强可察觉
  • 50 毫秒：明显感到迟滞
  • 启示：任何增加有效延迟超过 30 毫秒的武器晃动系统，都会损害瞄准性能。

3 速度 vs. 加速度敏感性

人类对绝对加速度的感知能力较弱，但对以下因素极为敏感：

  • 加速度噪声
  • 加加速度（加速度的导数）
  • 启示：必须对原始加速度信号进行滤波处理，或避免直接使用。

References:

  • Control systems derivative noise amplification
  • Human vestibular response studies

5. 基于感知极限推导出的参数范围

5.1 平移晃动（视图模型偏移）

模式 安全范围 理由
竞技 0.5–2.5 cm 低于有意识分心阈值
电影 2–6 cm 可见但可控
重型 3–10 cm 营造质量感幻觉

5.2 旋转晃动

旋转轴 上限 依据
Pitch ≤3° 超过此值会破坏瞄准基准
Roll ≤4° 玩家对翻滚的容忍度高于俯仰
Yaw ≤0.5° 偏航会破坏横向瞄准

5.3 时间常数 / 跟随速度

模式 τ（秒） 解释
竞技 ≤0.03 低于延迟最小可觉差
电影 0.1–0.3 产生可见惯性
重型 0.3–0.6 形成重量感知觉

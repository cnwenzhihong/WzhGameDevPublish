ARTICLE PARTIAL OVERRIDE ACTIVE

2026-05-08 2026-05-09 2026-05-09

常见概念

常见类

GameplayTag
用层级 Tag 管理 Ability 阻塞、免疫、Cooldown、State等等状态
AttributeSet
管理数值数据，方便其他系统的修改、回调和获取

基本关系

从代码结构上来看：ASC 是中枢，AttributeSet 存数值，Tag 存状态，GA 发起行动，GE 改变状态，GC 播表现。

⭐从架构设计上来看，可以看作数据驱动的MVC框架：
Model存数据：Tag存关键状态，AS管理随时会变成Tag的数值状态
View做表现：GC
Controller写逻辑：GA写大框架，GE写关键状态变更
ASC：统一处理多且杂的逻辑，降低耦合

注意点

ASC

初始化

原则：等玩家角色和Controller、State准备好后再初始化。
实践：Server 通常在 PossessedBy 调 InitAbilityActorInfo；Client 通常在 OnRep_PlayerState 后补 Init，LocalPredicted 报 not local，多半是Client这里漏了。

NetUpdateFrequency

PlayerState 默认更新频率低，Attribute/Tag 延迟会被误判成 GAS 延迟。

Ability List Lock

ActivatableAbilities 时使用 ABILITYLIST_SCOPE_LOCK，避免遍历期间移除 Ability 造成容器变化。

GA

ReplicateMode：Mix的GE只给Own client，minimal只同步Cue/Tag，给除了外加角色外其他的。

GA的生命周期

Input -> CanActivate -> Activate -> Commit -> TargetData/Task -> Apply GE -> End

Input：输入映射到 ASC 或由 GameplayEvent 激活

CanActivate
检查 Tag、Cost、Cooldown、Net Policy

CommitAbility
Commit 会再次 CheckCost/CheckCooldown，是能力执行真正效果的最后关口。

⭐Net Execution Policy
Local Predicted 先 client 后 server；
Server Only 只 server；
Local Only 只本地表现；
Server Initiated 先 server 后 owning client。
模拟端不执行 GA。

Attributes

Instant/Periodic 改 BaseValue；Duration/Infinite 通过 Modifier 影响 CurrentValue。

Meta Attribute

Damage 这类临时传输值适合做 Meta Attribute：GE 传入伤害，AttributeSet 再决定扣 Shield 还是 Health。
Lyra中就包含Damage和Heal两个Meta Attribute。

仅仅是概念，GAS并没有单独做成一个类型，所以用完需要手动归0。

Clamp 位置

PreAttributeChange 适合夹 CurrentValue；PostGameplayEffectExecute 适合处理 Instant GE 后的 BaseValue 和 Gameplay 事件，包括处理Damage事件

GameplayEffect：状态变化的唯一标准件

复杂公式用 MMC 或 ExecCalc，动态参数用 SetByCaller，来源信息放 GameplayEffectContext。

GE 三问：持续多久？改什么 Attribute/Tag？能不能被预测？

Duration Type

Instant 用于永久变化；Duration 有到期时间；Infinite 需要手动移除。
Periodic 表现像周期性 Instant，不能预测。

运算类型

MMC
MMC 返回一个 float，可捕获 Source/Target Attribute，可预测，适合 Cost、Cooldown、可预测数值。

ExecCalc
ExecCalc 能一次改多个 Attribute，适合 Damage 结算、护甲减伤、暴击，但不能预测且必须 C++。
不是大问题，一般数值运算都以服务器为准，ULyraDamageExecution甚至只在服务器运行。

Question

什么时候用 MMC，什么时候用 ExecCalc？

需要一个可预测 float 用 MMC，比如 Cost、Cooldown、Buff 数值；
需要权威复杂结算、改多个 Attribute 或做暴击护甲吸血时用 ExecCalc，不需要客户端预测结果、很重要的运算。

AbilityTask 与 Targeting：把异步流程从 GA 中拆出来

AbilityTask 负责等待、同步、TargetData、Montage、RootMotion 等跨帧行为。
TargetData 是 client 与 server 之间传目标的标准载体。

GA 写主线，AbilityTask 写等待；TargetData 不只是目标 Actor，也可以是 hit result、location、custom data。

Question

为什么需要 AbilityTask

GA 激活后的逻辑常常跨帧：等输入释放、等 Montage event、等目标确认。Task 把这些 latent 行为封装成可复用节点。

⭐TargetData

TargetData 是网络传输目标选择结果的协议。Projectile 可只 server spawn；Hitscan 常由 client 生成 TargetData 再 server 验证。

Question

TargetData如何收发？

⭐WaitNetSync

需要在 AbilityTask 回调后继续预测 GE 时，用 WaitNetSync OnlyServerWait 开新 Scoped Prediction Window

GameplayCue：表现层要轻，Authority 要清

 用 GameplayTag 触发，常用于粒子、音效、摄像机反馈。

生命周期：
 Instant GE 对应 Execute；Duration/Infinite 对应 Add/Remove/WhileActive。

可靠性低
很多 Cue 通过 unreliable NetMulticast 触发。关键状态不要只依赖 Cue，可靠状态应来自 GE/Tag/Attribute。

本地 Cue
纯表现可以本地触发，减少网络带宽

⭐批处理
大量 Cue 可考虑 batching 或精简 GameplayCueParameters

Prediction：只预测能承受回滚的东西

Prediction Key 生命周期

Client 激活 GA 生成 key，CallServerTryActivateAbility 时携带 key给 server；
client 预测 GE 带同一个 key；server 复制结果和 key 回来；client 清掉自己预测的临时 GE。

能预测什么

Ability activation、Montage、Attribute Modifier、Tag、Cue、部分 RootMotion。
ExecCalc 和 GE removal 不能可靠预测。

预测伤害会出现血量回跳，预测死亡更糟。通常伤害用 server ExecCalc 权威结算，本地只预测自己主动触发的动作。

Cooldown 问题

低 cooldown 时间的技能会让高延迟玩家吃亏。
大型项目可用自定义 bookkeeping 替代纯 Cooldown GE。

常见能力测试

把需求翻译成 GAS 组合

怎么做 Sprint/Stun/Crit
重点：说 GA、GE、Tag、Attribute、Prediction 怎么组合

需求翻译模板：触发方式 -> 权威端 -> GE 类型 -> Tag 阻塞 -> Cue 表现 -> 是否预测。

Stun
Duration GE 授予 State.Stunned Tag；该 Tag 阻塞移动/技能；GC 播晕眩表现；必要时 CancelAbilitiesWithTag。

Sprint
Local Predicted GA；Duration/Infinite GE 改 MoveSpeed；周期 Cost 扣 Stamina；低资源时 EndAbility。

Critical Hit
命中后 server ExecCalc 判定暴击，把倍率、随机种子或结果写进 GE/Context/Cue 参数，client 只播表现。

One Button Interaction
用 TargetData 或可交互接口收集候选，GA 根据 GameplayTag/priority 选择门、拾取、对话等具体行为。

能力 GAS 组合 面试风险点
Stun Duration GE + State Tag + Blocked Ability Tags + GC 别只停输入，要处理正在运行的 Ability
Sprint Predicted GA + MoveSpeed GE + Stamina Cost Cost 周期预测需要新的 Prediction Window
ADS Predicted GA + Camera/MoveSpeed 本地反馈 射击命中仍需 server validation
Lifesteal Damage ExecCalc 后按实际伤害 Heal 不要按输入伤害吸血，要按最终伤害

Debug 与优化：能定位问题才像能独立负责

排查路径：看 ASC、看 Tag、看 GE、看 Ability 激活失败原因、看复制模式。

四步排查：ASC 是否 Init -> Tag/Cost/Cooldown 是否阻塞 -> GE 是否应用/复制 -> Prediction Key 是否 stale。

Question

AbilityTask 的价值是什么？

GA 负责主流程，AbilityTask 封装跨帧等待和网络同步，如 WaitTargetData、WaitGameplayEvent、PlayMontageAndWait、RootMotion。这样逻辑可复用，也更容易处理预测窗口。

Question

你会怎么实现 Sprint？

Sprint 用 Local Predicted GA，激活后应用 MoveSpeed GE，周期扣 Stamina。Stamina 不足或松开输入时 EndAbility。周期扣资源若要预测，需要 WaitNetSync 开新的 Scoped Prediction Window。
在CMC内部实现Sprint的网络预测功能，GA提前配置好各个移动状态的数值。

Question

你会怎么实现 Stun？

Stun 是 Duration GE，授予 State.Stunned Tag；该 Tag 阻塞移动和施法，也可以 CancelAbilitiesWithTag 中断已运行 Ability；表现用 GameplayCue。

Question

遇到 Ability 激活失败，你怎么排查？

先确认 ASC 在 client/server 都 Init；用 showdebug abilitysystem 看 Owned Tags、Blocked Tags、Cost/Cooldown；开 Activation Failed Tags 和 LogAbilitySystem；最后查 Prediction Key 是否 stale。
